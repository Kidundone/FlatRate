# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Flatrate Buddy (marketed name; repo/package name `flat-rate-tracker`) — a pay-tracking and pay-protection
app for flat-rate automotive technicians. Lets a tech log jobs/hours fast, catch short-pays, track
comebacks, and (Pro tier) audit a pay stub or generate a dispute PDF. Also has a shop/team dashboard for
service managers. Live at app.nellylabs.dev. Ships as a PWA (web) and as a native iOS app via Capacitor.

## Commands

```bash
node build.mjs              # bundle src/*.js -> app.<hash>.js, hash app.css, rewrite HTML refs, regen sw.js, copy to www/
node --check app.src.js     # syntax-check the generated bundle (closest thing to a test suite — see TEST-CHECKLIST.md)
npm run cap:sync            # build + npx cap sync (pushes web assets into the iOS project)
npm run cap:ios             # build + cap sync ios + open Xcode
```

There is no automated test runner. `TEST-CHECKLIST.md` is a manual QA checklist — walk it after any
change touching the entry form, missing-work detection, or proof/export fields.

**Never hand-edit `app.src.js`, any `app.<hash>.js`/`app.<hash>.css`, `sw.js`, or anything under `www/`
or `ios/App/App/public/`.** All of those are generated by `build.mjs` from `src/*.js` + `app.css`. Edit
the real sources and rebuild.

### Deploy path (web)

A `pre-push` git hook (`.git/hooks/pre-push`) runs `node build.mjs` automatically and auto-commits the
resulting bundle-hash changes before the push goes out — so `git push` alone regenerates and ships the
build. Cloudflare Pages serves the repo root directly (`_redirects`, `_headers`, `404.html` live there).
If you edit `HTML_FILES` in `build.mjs` (which HTML files get their script/CSS refs rewritten), update the
`git add` file list in the pre-push hook to match — they drifted out of sync once before (see the comment
in the hook) and silently left rebuilt hash references uncommitted in files the hook didn't know about.

### Deploy path (iOS)

`npm run cap:sync` (or `cap:ios` to also open Xcode) copies `www/` into `ios/App/App/public/`. Native
Swift changes (anything under `ios/App/App/*.swift`) need an actual Xcode rebuild on device/simulator —
there is no way to hot-push a native change the way web bundle changes ship on `git push`.

### Supabase

Edge functions live in `supabase/functions/*/index.ts` (scan-ro, scan-paystub, cluster-job-types,
draft-dispute, create-checkout-session, stripe-webhook) and are deployed via the Supabase dashboard/CLI,
not via this repo's build. Migrations are plain timestamped SQL files in `supabase/migrations/`, applied
in filename order — check the latest one before assuming the schema; it moves.

## Architecture

### Single bundled JS file, order-dependent concatenation

`build.mjs` concatenates `src/*.js` in this exact order into one `app.src.js`, then minifies it with
esbuild into `app.<hash>.js`:

```
classification-service.js → data-service.js → utils.js → photo-service.js
→ main-page.js → more-page.js → claims-service.js → boot.js
```

Nothing is a module — every file shares one global scope, so a later file can call a function defined in
an earlier one with no import. This means **file order in `SOURCE_PARTS` matters**: a function used
before its defining file runs will be `undefined` at call time, not at parse time, so the failure shows
up as a runtime error in whatever feature touches it, not a build error. `boot.js` runs last on purpose —
it's where DOM-ready wiring and the app's `runOnce()` boot sequence live, and it expects every other
module's functions to already exist as globals.

### Content-hashed bundle, cache strategy in `sw.js`

`app.<hash>.js` / `app.<hash>.css` are content-addressed (SHA1 of the built output, first 10 hex chars).
`build.mjs` regenerates `sw.js` from a template on every build with the new hash baked in. The caching
split (see comment block in `build.mjs`): HTML is always network-first (never served stale — this is
what guarantees a phone always has HTML pointing at the current hash), hashed JS/CSS is cache-first
(immutable by construction), everything else (icons, manifest) is network-first with an offline
fallback. **If a build ships a new JS/CSS hash but the referencing HTML doesn't get committed/deployed
in the same push, the site 404s on its own bundle** — this has happened before; it's why the pre-push
hook's file list has to stay in sync with `HTML_FILES` in `build.mjs`.

### SPA shell, not multi-page

`index.html` is a single-page app covering Log / Stats / More via `showSpaPage()` in `boot.js` — pages
are `position: fixed` panels slid on/off screen with CSS transforms (`#spa-more`, `#spa-stats`), never
`display: none` (WKWebView excludes `display:none` subtrees from its touch hit-test tree and doesn't
reliably re-add them — this bit the app once already). `more.html` is now just a redirect stub into
`index.html?goto=more`; don't add real content there. `team.html` and `dashboard.html` are separate real
pages (manager/shop dashboard, not part of the tech-facing SPA shell).

### OCR pipeline

Photo of a repair order / get-ready sheet → uploaded → `supabase/functions/scan-ro` calls Gemini
(`gemini-2.5-flash`) with a prompt that extracts RO #, VIN, stock #, job list, and per-job hours,
including handwriting-reading rules and VIN-character-confusion correction (O/I/Q). Client-side,
`photo-service.js` ranks candidate jobs and picks hours with this priority: **personal learned hours for
that tech+job (`STORES.types`, `lastHours`) beat book/flat time**, and manual entry always beats both.
`getEntryReviewState(...)` in `utils.js` is the shared model both the Log page and More-page review queue
render from (OCR waiting/failed/ready/mismatch/needs-review) — extend that, not two parallel copies.

### Native iOS quirks already worked around

- `ios/App/App/MainViewController.swift` force-disables horizontal scroll bounce
  (`alwaysBounceHorizontal = false`) and pins pinch-zoom to 1.0 scale at the `UIScrollView` level, and
  **re-asserts the bounce setting on every keyboard show/hide notification** — iOS's automatic
  content-inset adjustment (`ios.contentInset: "automatic"` in `capacitor.config.json`) silently
  re-enables it each time the keyboard opens otherwise.
- Xcode's GPU Frame Capture debug instrumentation can trip WKWebView's unresponsive-process watchdog and
  black-screen the app while debugging on a real device — not a code bug; fix is disabling GPU Frame
  Capture in the Run scheme, not touching the app.
- `overscroll-behavior-x: none` on `html`/`body` stops page-level rubber-banding but does **not** stop an
  individual `overflow-x: auto` child from bouncing on its own edges — those need their own
  `overscroll-behavior-x: contain` (see the chip/tool-row selectors in `app.css` for the pattern).

### Data model

Supabase Postgres is the source of truth (`work_logs` table + `proofs` storage bucket for photos).
Manual field values always win over OCR suggestions until a user explicitly taps an apply button — OCR
never silently overwrites `ro_number` or `vin8`. Teams/shops (`supabase/migrations/20260715_teams.sql`
onward) add manager roles, roster management, and a claims/requests inbox (`claims-service.js` +
`team.html`) for pay-dispute workflows, layered on top of the same per-tech `work_logs` rows.

## Repo housekeeping notes

- `ARCHITECTURE.md` predates the SPA merge, the Supabase migration, and most of the Pro/team features —
  treat it as historical, not current; this file supersedes it for anything that conflicts.
- `.claude/worktrees/` may contain stale isolated-agent worktrees from prior sessions; not part of the
  shipped app.
- `node_modules` has no bundled `esbuild` binary guarantee across environments — `build.mjs` falls back to
  unminified output if esbuild's native binary doesn't match the current OS/arch. An unminified
  `app.src.js`-equivalent output is fine for a local syntax check but **must not be committed** as a real
  build.
